Django==5.2.17
argon2-cffi==25.1.0
Pillow==12.3.0
# 角かっこは「追加機能（extras）」の指定。
# 必要な依存を allauth 自身に決めさせる。
#
#   mfa            … TOTP と パスキー（qrcode, fido2）
#   socialaccount  … Google / GitHub ログイン（requests, requests-oauthlib ほか）
#
# 9日目までは qrcode と fido2 を手で並べていた。
# それでも動いていたのは、開発機の仮想環境に requests が
# 別の経路で入っていたからで、宣言としては間違っていた。
# 手で書き写すと、上流が依存を増やしたときに気づけない。
#
# ★65.18.0 のまま据え置いている（判断日: 2026-08-11）★
#
# 上流で 65.19.0 が出ている（2026-08-06 公開）。修正内容は
# `IDP_OIDC_ID_TOKEN_EXPIRES_IN` を設定しても読まれず、ID トークンの
# 有効期限が常に既定の 300 秒になる、というもの。
#
#   65.18.0:  def ID_TOKEN_EXPIRES_IN(self) -> int: return 5 * 60
#   65.19.0:  def ID_TOKEN_EXPIRES_IN(self) -> int:
#                 return self._setting("ID_TOKEN_EXPIRES_IN", 5 * 60)
#
# **KururuCMS はこの不具合の対象外**。この設定は allauth 自身が
# OpenID Connect の Identity Provider（トークンを発行する側）として
# 動くときのもので、そのためには `allauth.idp.oidc` を INSTALLED_APPS へ
# 入れる必要がある。この CMS は入れていない。
# Google / GitHub ログインは「発行されたトークンを受け取る側」なので別物。
#
# 対象外だが、上げないという判断は次のとおり:
#
#   * 65.19.0 にはこの修正以外の変更も含まれる。認証は壊れたことに
#     気づきにくい場所なので、連載の途中で黙って版を変えない。
#   * 記事の本文・スクリーンショット・タグ（day-08 / day-09）は
#     65.18.0 の挙動で書いてある。版だけ動かすと記事と実物がずれる。
#   * 公式リリースノートでも Security notice ではなく Fixes 扱いで、
#     CVE も付いていない。緊急に上げる根拠が無い。
#
# 上げるときは、版だけ差し替えて終わりにしない。
# 全テストを通し、記事の該当箇所も一緒に直す。
django-allauth[mfa,socialaccount]==65.18.0
